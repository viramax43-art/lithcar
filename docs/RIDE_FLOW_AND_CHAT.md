# Чат поездки, уведомления в приложении и логика «Еду на точку / Прибыл»

Документ описывает, **какие проблемы были** в старом флоу и **как они закрыты** в текущей реализации.
Дата: 2026-10-14. Реализовано: бэкенд (`app/services/ride_status_service.py`, `ride_chat_service.py`,
`ride_notification_service.py`), API (`/api/v1/rides/*`, `/api/v1/driver/cabinet/rides/*`), UI
(пассажир — карточка заявки, водитель — карточка точки на карте).

## 1. События поездки приходили только в Telegram

**Было.** Сообщения «назначен водитель», «водитель уже едет», «водитель приехал» уходили только в бота.
Пассажир открывал приложение и не видел, что водитель уже рядом; водитель не видел отмену/готовность пассажира.

**Стало.** Каждое событие пишется в ленту уведомлений приложения **и** в Telegram, для обеих сторон:
назначение, «еду», «прибыл», старт, завершение, отмена, неявка, новое сообщение чата.
Лента в приложении объединяет события поездок и админские инфо-блоки, есть счётчик непрочитанных,
«прочитать всё» и переход по тапу в конкретную поездку (`payload.rideId`).

## 2. Чат водителя с попутчиками

**Было.** Чата не было вообще: у водителя и пассажира не было способа связаться, кроме звонка/Telegram.

**Стало.** Общий чат «машины»: водитель + все пассажиры группы.
- Тред: `g:<group_id>` для сгруппированных заявок, `r:<ride_id>` для одиночной.
- Сообщения, быстрые ответы («Я на месте», «Где вы?», «Еду, 5 минут», «Не могу вас найти»), непрочитанные счётчики и галочка «прочитано».
- В чат автоматически попадают системные записи о статусах — это история поездки для разбора спорных случаев.
- Сообщения дублируются в Telegram собеседникам (чтобы не пропустить), с кнопкой «Открыть кабинет».

## 3. Возможные проблемы и как они закрыты

| Проблема | Решение |
|---|---|
| Водитель нажал «Еду» за часы до подачи — пассажир ждёт на улице | Запрет раньше `RIDE_EN_ROUTE_MAX_EARLY_MINUTES` (360 мин); UI показывает, с какого времени можно отметить |
| Двойной тап / второе устройство | Идемпотентность: повторный перевод не ошибка и не дублирует уведомления (журнал `ride_status_events` — одна запись) |
| Водитель промахнулся по кнопке («Прибыл»/«Начал») | Откат в окне `RIDE_STATUS_UNDO_WINDOW_MINUTES` (5 мин), пассажир видит корректировку в приложении (без Telegram-спама) |
| Водитель забыл нажать «Еду», но приехал | «Прибыл» прямо из «назначен» — принимаем, факт выезда фиксируем автоматически |
| Пассажир не выходит, водитель ждёт | Напоминание пассажиру через `RIDE_WAIT_REMINDER_MINUTES` (7 мин), и только после `RIDE_NO_SHOW_MIN_WAIT_MINUTES` (5 мин) доступна кнопка «Пассажир не вышел» |
| Водитель «уехал через 10 секунд» | Неявку нельзя оформить без отметки «Прибыл» и минимального ожидания; пассажиру уходит текст с причиной, админам — уведомление |
| Пассажир не может найти машину / ошибся точкой | Чат и быстрые ответы, редактирование точки подачи (существующий флоу с подтверждением), «Где вы?» с кулдауном 3 мин |
| Отмена в последний момент | Поздняя отмена (водитель уже едет/ждёт) помечается отдельной причиной, водитель видит предупреждение и теряет время «по документам» |
| Отмена после старта | Запрещена в приложении: «свяжитесь с водителем в чате» (защита от «покатались и не заплатили») |
| Статус «завис» (водитель пропал) | Фоновый сторож (`ride_watchdog`, 60 с): напоминания, подсказки, пометка «требует внимания администратора» с причиной |
| Водитель не нажал «Завершил» — поездка висит «в пути» | Через **2× расчётного времени в пути** пассажиру автоматически уходит вопрос «Поездка состоялась?» с кнопками **[Да] / [Нет]** (приложение + Telegram): «Да» закрывает поездку, «Нет» — эскалация администратору, молчание — тоже под контроль админа |
| Водитель отметил прибытие далеко от точки | Фиксируется расстояние (`arrival_distance_m`); при > `RIDE_ARRIVAL_RADIUS_METERS` поездка помечается для админа, факт остаётся в журнале |
| Спам в чате / кнопкой «Где вы?» | Лимит 20 сообщений/мин, кулдаун «Где вы?» 3 мин, объединение уведомлений о переписке в одно («свежее» сообщение в одной карточке) |
| Заблокированные друг с другом участники | Чат для них закрыт (как и раньше — назначение/выбор заявки) |
| Спорные ситуации | Журнал `ride_status_events` (кто, когда, что, причина, координаты) + причины отмен и пометки администратора |
| Неверное сообщение в чате (пустое/слишком длинное) | Валидация на сервере: пустое — ошибка, максимум `RIDE_CHAT_MAX_LENGTH` (1000 символов) |

## 4. Поездка не закрыта: «Поездка состоялась?» (кнопки [Да] / [Нет])

**Было.** Водитель нажимал «Начал поездку», но не нажимал «Завершил»: поездка навсегда оставалась
`in_progress`, пассажир не понимал, состоялась она или нет, а деньги/статистика «не двигались».
Никакой логики авто-проверки не было — только ручной разбор.

**Стало.** Сторож (`ride_watchdog`) сам считает, сколько примерно ехать из A в B:

| Источник оценки | Когда используется |
|---|---|
| `quote_duration_min` (маршрутная оценка при расчёте цены) | Есть оценка OSRM/формулы — берём её |
| `quote_road_km` → время по средней скорости | Есть дорожные километры |
| Прямая дистанция × 1.3 → время по скорости | Нет готовых километров (короткие/простые маршруты) |
| `RIDE_COMPLETION_CHECK_FALLBACK_MINUTES` | Данных о маршруте нет вообще |

Далее задержка = **оценка × `RIDE_COMPLETION_CHECK_FACTOR` (2)**, ограниченная снизу
`RIDE_COMPLETION_CHECK_MIN_MINUTES` (20 мин) и сверху `RIDE_COMPLETION_CHECK_MAX_MINUTES` (360 мин).
Когда задержка истекла, а поездка всё ещё `in_progress`:

1. Пассажиру уходит вопрос «Поездка состоялась?» — карточка в ленте уведомлений **с кнопками [Да]/[Нет]**,
   кнопки в Telegram (inline) и блок в карточке поездки, чтобы вопрос не потерялся.
   Вопрос задаётся один раз; в payload — `requiresConfirmation`, `expectedMinutes`, `elapsedMinutes`, `rideId`.
2. **«Да»** → поездка закрывается от имени пассажира (`ride_status_events`: actor `passenger`), водитель
   получает уведомление «поездка закрыта — пассажир подтвердил», кнопки исчезают.
3. **«Нет»** → статус остаётся `in_progress`, но поездка помечается `passenger_not_completed`:
   администратор получает уведомление, водитель — предупреждение, в чат пишется системная запись.
4. **Молчание** дольше `RIDE_COMPLETION_CHECK_ESCALATE_MINUTES` (60 мин) → пометка `completion_unconfirmed`
   и админ-контроль (повторно вопрос не задаётся, пассажира не спамим).

Повторные клики (второй тап, ответ из Telegram после ответа в приложении, ответ после закрытия поездки)
идемпотентны: состояние не меняется, уведомления не дублируются.

## 5. Настройки (backend/.env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `RIDE_EN_ROUTE_MAX_EARLY_MINUTES` | 360 | Насколько заранее можно нажать «Еду на точку» |
| `RIDE_STATUS_UNDO_WINDOW_MINUTES` | 5 | Окно отката ошибочной отметки |
| `RIDE_ARRIVAL_RADIUS_METERS` | 400 | Радиус «прибыл на точку» для контроля |
| `RIDE_WAIT_REMINDER_MINUTES` | 7 | Напоминание пассажиру, что водитель ждёт |
| `RIDE_NO_SHOW_MIN_WAIT_MINUTES` | 5 | Минимальное ожидание для оформления неявки |
| `RIDE_DRIVER_LATE_REMINDER_MINUTES` | 15 | Напоминание водителю после времени подачи |
| `RIDE_EN_ROUTE_TIMEOUT_MINUTES` | 90 | «Едет» дольше — под контроль админа |
| `RIDE_MAX_DURATION_MINUTES` | 360 | Поездка дольше — под контроль админа |
| `RIDE_CHAT_MAX_LENGTH` | 1000 | Максимальная длина сообщения |
| `RIDE_CHAT_RATE_LIMIT_MESSAGES` / `..._WINDOW_SECONDS` | 20 / 60 | Антиспам в чате |
| `RIDE_NUDGE_COOLDOWN_SECONDS` | 180 | Кулдаун «Где вы?» |
| `RIDE_WATCHDOG_INTERVAL_SECONDS` / `RIDE_WATCHDOG_ENABLED` | 60 / true | Период работы сторожа поездок |
| `RIDE_COMPLETION_CHECK_FACTOR` | 2 | Множитель к расчётному времени в пути для вопроса «Поездка состоялась?» |
| `RIDE_COMPLETION_CHECK_MIN_MINUTES` | 20 | Нижняя граница задержки вопроса (короткие поездки) |
| `RIDE_COMPLETION_CHECK_MAX_MINUTES` | 360 | Верхняя граница задержки вопроса |
| `RIDE_COMPLETION_CHECK_SPEED_KMH` | 45 | Средняя скорость для оценки времени по дистанции |
| `RIDE_COMPLETION_CHECK_FALLBACK_MINUTES` | 60 | Оценка по умолчанию, если данных о маршруте нет |
| `RIDE_COMPLETION_CHECK_ESCALATE_MINUTES` | 60 | Сколько ждём ответ пассажира до подключения администратора |

## 6. API (кратко)

Пассажир: `GET /api/v1/rides/{id}/flow`, `GET|POST /api/v1/rides/{id}/chat`, `POST .../chat/read`,
`POST .../ready` («я на месте»), `POST .../nudge` («где вы?»), `POST .../cancel`,
`POST /api/v1/rides/{id}/completion-confirmation` (тело `{"completed": true|false}` — ответ на
«Поездка состоялась?»; в ответе — актуальный `flow`, в т.ч. `canConfirmCompletion`).

Водитель: `GET /api/v1/driver/cabinet/rides/{id}/flow`, `POST .../en-route`, `.../arrived`, `.../start`,
`.../complete`, `.../undo`, `.../no-show`, `.../cancel`, `GET|POST .../chat`, `POST .../chat/read`.

Ошибки перехода возвращают код и подсказку для UI: `too_early` (+`canStartAt`), `no_show_too_early`
(+`availableInSeconds`), `undo_window_expired`, `ride_closed`, `nudge_cooldown` (+`retryAfterSeconds`).
