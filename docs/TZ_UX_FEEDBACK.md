# ТЗ: UX / операционка Ride (из фидбека владельца)

Дата: 2026-09-27  
Проекты: `lithcar` (web) + `ride` (Android shell)  
Цель: long-route операционка (направление + фьючер), не «поездка в магазин».

---

## Роли для прогона

| Роль | Кабинет | Цвет-баннер |
|------|---------|-------------|
| Пассажир | `/ride/` | синий/нейтральный |
| Водитель | `/ride/driver` | зелёный |
| Админ / модератор | `/ride/admin` | отдельный shell |

Проверять **свободным** юзер-аккаунтом + тремя сценариями водителя (мои / свободные / офферы).  
Отдельная сессия screen-share — после закрытия пунктов ниже.

---

## P0 — ломает оперативку

### A1. Админ: отмена точки при рисовании зоны
- **Есть:** отмена всей зоны, undo в сайдбаре.
- **Проблема:** на мобилке кнопки «отменить точку» не видны (сайдбар закрыт / перекрыты фильтром).
- **Нужно:** всегда видимая панель при рисовании: **Отменить точку | Отменить зону | Сохранить**.
- Undo последней вершины одним тапом; Save при ≥3 точках.

### A2. Админ: после сохранения зоны — направление
- После Save зоны модалка: **Откуда → Куда** (два поля / пара зон).
- Сохранять на зоне: `directionFrom`, `directionTo` (+ отображаемое `directionLabel`).
- Направление — основа long-route алгоритма (водитель видит коридор, не уточняет адрес в переписке).

### A3. Админ: фильтр периода
- На мобилке time-input обрезан (`00:0` / `23:5`) из‑за `width: 64px`.
- Фильтр должен корректно матчить день/время заявки (`dateTimeLocal` / Europe/Vilnius).
- «Сегодня / Завтра / Послезавтра / Все» + диапазон времени без обрезки.
- Счётчик заявок = то, что реально на карте.

### A4. Пассажир: нет баланса → «Оплатить через водителя»
- Никогда не показывать сырой код `insufficient_points`.
- Текст: недостаточно поинтов + CTA **«Оплатить через водителя»** (`driver_cash`).
- И для новой заявки, и для брони оффера.

### A5. Перевод баланса любому по ID
- Backend уже без ролевых ограничений.
- UI перевода должен быть у пассажира, водителя, админа/модератора (у всех есть ID).
- Подсказка: можно слать пассажиру / водителю / админу / модератору.

## P1 — кабинет водителя

### D1. Главный CTA «направление / фьючер»
- На первом экране водителя: кнопка **Поставить направление** (откуда / куда / места / когда).
- Не прятать только в боковом меню → «Мои предложения».

### D2. QR без in-app камеры
- Не запрашивать доступ к камере приложения.
- Пассажир: одноразовый QR/ссылка.
- Водитель: сканирует **системной** камерой → открывается confirm-страница `/ride/qr/:token` → зачисление.
- В меню водителя — ручной ввод кода (fallback), без `getUserMedia`.

### D3. Навигация driver ↛ passenger
- Из `/driver` нельзя «провалиться» на пассажирский `/` / `/profile` по свайпу/кнопке Назад.
- Route-guard для driver shell; регистрация не ведёт на passenger Profile без явного выхода.

### D4. Свободный заказ: A→B «по воздуху»
- При активном фьючере/свободном заказе водитель видит **две точки** (откуда + куда) и **прямую линию**.
- Уже частично есть в `DriverMap`; проверить режим `available` и что dropoff всегда приходит в map payload.

### D5. Геолокация водителя
- Фактическая позиция на карте должна обновляться (watch + heartbeat).
- Не уводить в пассажирский экран при жестах.

### D6. Лишнее «от–до» в профиле водителя
- Убрать/не показывать персональные «работаю с … до …», если это не редактируемый профиль.
- Глобальные work hours — только в админ-настройках слотов.

## P2 — продукт / процесс

- Цветовая инфографика ролей на баннере кабинета (уже частично: `CabinetRoleBanner`).
- Совместный прогон через screen-share после P0/P1.
- Android `ride` shell: не ломать deep-link `/ride/qr/:token` и `/ride/driver/enter/:token`.

---

## Критерии приёмки (коротко)

1. Модератор на телефоне рисует зону → undo точки без открытия сайдбара → Save → вводит направление.
2. Фильтр «Завтра 09:00–12:00» показывает ту же заявку, что создал пассажир на завтра.
3. Пассажир с 0 поинтов видит «Оплатить через водителя», не `insufficient_points`.
4. Перевод по ID работает между любыми ролями.
5. Водитель с главной ставит направление/фьючер в ≤2 тапа.
6. QR пассажира открывается системной камерой; камера Mini App не запрашивается.
7. Водитель в режиме свободных видит A→B линию и не попадает на passenger UI.
